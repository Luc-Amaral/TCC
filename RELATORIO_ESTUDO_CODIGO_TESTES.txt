RELATORIO DE ESTUDO DO CODIGO
VPN SECURITY TESTER
=====================

Objetivo deste documento
------------------------
Este documento explica, de forma didatica, como o codigo funciona. Ele descreve o fluxo completo da aplicacao, os modulos, as funcoes, os parametros, os retornos, as capturas de pacotes e a forma como o resultado final e calculado.

O projeto nao e um verificador absoluto de seguranca criptografica. Ele e uma ferramenta experimental de auditoria de isolamento de trafego e comportamento de uma VPN em cenarios controlados.


1. VISAO GERAL DA ARQUITETURA
==============================

O projeto possui quatro camadas principais:

1. main.py
   Entrada do programa e organizacao da preparacao.

2. utils/network.py
   Descoberta de IPs, DNS, interfaces, processos VPN, gateway e rotas.

3. core/nucleo_exec.py
   Orquestracao dos testes, politica de resultados e relatorio.

4. tests/
   Implementacao dos testes de payload, HTTP, privacidade, rotas, kill switch e testes automatizados.

Fluxo resumido:

main.py
  |
  +-- obter_ips_reais()
  +-- obter_dns_real()
  +-- detectar_ambiente_vpn()
  |     +-- detectar interface VPN
  |     +-- detectar processo VPN
  |     +-- detectar interface fisica
  |
  +-- VPNSecurityTester(...)
        |
        +-- teste 1: isolamento de payload
        +-- teste 2: isolamento HTTP
        +-- teste 3: privacidade IPv4/IPv6/DNS/DoH/DoT
        +-- teste 4: isolamento de rotas
        +-- teste 5: kill switch
        +-- politica final
        +-- relatorio JSON


2. FLUXO DE EXECUCAO DO MAIN.PY
================================

Arquivo: main.py

O arquivo main.py e o ponto de entrada. Ele nao contem a logica detalhada de captura. Sua responsabilidade e preparar o ambiente e chamar o orquestrador.

2.1 Imports
-----------

argparse
- Permite ler argumentos como --sem-prompt e --salvar-relatorio.

sys
- Permite encerrar o programa com sys.exit() ou SystemExit.

VPNSecurityTester
- Classe que executa a bateria de testes.

Funcoes importadas de utils.network
- detectar_ambiente_vpn
- interface_esta_ativa
- listar_interfaces_ativas
- obter_detalhes_interface
- obter_dns_real
- obter_ips_reais

2.2 _parse_args()
-----------------

Responsabilidade:
- Ler as opcoes informadas no terminal.

Argumentos:

--interface-vpn
- Permite substituir a interface VPN detectada automaticamente.

--interface-fisica
- Permite substituir a interface fisica detectada automaticamente.

--nome-vpn
- Permite informar explicitamente o processo, mas e opcional.
- O projeto tenta descobrir o processo automaticamente primeiro.

--sem-prompt
- Evita perguntas interativas de confirmacao.

--salvar-relatorio
- Solicita que o resultado seja salvo em arquivo JSON.

Retorno:
- Um objeto argparse.Namespace contendo as opcoes.

2.3 _confirmar_interface_fisica()
----------------------------------

Parametros:
- interface_fisica: nome da interface detectada.
- modo_silencioso: indica se --sem-prompt foi usado.

O que faz:
1. Mostra o nome da interface.
2. Consulta IPs e gateway usando obter_detalhes_interface().
3. Lista outras interfaces ativas.
4. Permite confirmacao manual.
5. No modo silencioso, aceita a interface sem input().

Retorno:
- Nome da interface escolhida.

2.4 Bloco principal
-------------------

Quando main.py e executado diretamente, o bloco __main__:

1. Le os argumentos.
2. Executa obter_ips_reais().
3. Executa obter_dns_real().
4. Interrompe se o baseline IPv4 ou DNS estiver ausente.
5. Solicita que o usuario conecte a VPN.
6. Executa detectar_ambiente_vpn().
7. Aplica substituicoes de argumentos, se existirem.
8. Pede apenas interfaces ausentes.
9. Nao pede mais o processo manualmente.
10. Usa o texto nao-detectado se nao encontrar processo.
11. Confirma a interface fisica.
12. Verifica se as interfaces estao ativas.
13. Cria VPNSecurityTester.
14. Executa run_all_tests().

Se o processo nao for detectado:
- Os testes de trafego continuam.
- O teste de kill switch retorna INCONCLUSIVO.
- O programa nao encerra um processo desconhecido.


3. MODULO utils/network.py
===========================

Este modulo concentra informacoes do sistema operacional e da rede.

3.1 _interface_e_vpn(interface_name)
------------------------------------

Recebe:
- Nome da interface.

Processamento:
- Converte o nome para minusculas.
- Procura palavras como tun, tap, wg, vpn, hoxxvpn e outras.

Retorno:
- True quando o nome parece ser uma interface VPN.
- False caso contrario.

Limitacao:
- E uma heuristica. Uma VPN com nome incomum pode nao ser detectada.

3.2 obter_tabela_rotas()
-------------------------

Responsabilidade:
- Capturar a tabela de rotas do sistema.

No Windows:
- Executa route print -4.

Em outros sistemas:
- Executa netstat -rn.

Retorno:
- Texto bruto da tabela de rotas.
- "Indisponivel" se ocorrer erro.

Uso:
- O kill switch guarda uma copia antes e outra depois da queda.
- Isso fornece evidencia estrutural, embora a comparacao automatica detalhada ainda seja limitada.

3.3 interface_esta_ativa(nome_interface)
------------------------------------------

Responsabilidade:
- Confirmar se uma interface existe e esta ativa.

Processamento:
- Consulta psutil.net_if_stats().
- Verifica a propriedade isup.

Retorno:
- True se a interface estiver ativa.
- False se nao existir ou ocorrer erro.

Uso:
- main.py impede a auditoria quando a interface VPN ou fisica esta inativa.

3.4 _obter_gateway_padrao()
----------------------------

Responsabilidade:
- Descobrir o gateway padrao.

No Windows:
- Usa route print 0.0.0.0 mask 0.0.0.0.

Em Linux/macOS:
- Tenta ip route show default.
- Depois netstat -rn.
- Depois route -n.

Retorno:
- Endereco do gateway.
- None quando nao consegue descobrir.

3.5 obter_informacoes_redes()
------------------------------

Responsabilidade:
- Criar um snapshot geral da rede.

Coleta:
- gateway_padrao;
- tabela_rotas;
- nomes de interfaces;
- IPs IPv4 e IPv6;
- isup;
- duplex;
- speed;
- mtu;
- flags.

Conversao JSON:
- Objetos psutil nao sao enviados diretamente ao json.dump().
- O status de cada interface e convertido para um dicionario simples.

Retorno aproximado:

{
  "gateway_padrao": "192.168.1.1",
  "tabela_rotas": "...",
  "interfaces": {
    "Ethernet": {
      "ips": ["192.168.1.25"],
      "status": {
        "isup": true,
        "duplex": 2,
        "speed": 1000,
        "mtu": 1500,
        "flags": "..."
      }
    }
  }
}

3.6 detectar_interface_fisica(interface_vpn=None)
---------------------------------------------------

Responsabilidade:
- Escolher a interface fisica mais provavel.

Ignora:
- loopback;
- interface VPN conhecida;
- Docker;
- VirtualBox;
- VMware;
- bridges;
- interfaces virtuais comuns.

Pontuacao:
- Interface com IP recebe pontos.
- Nome contendo Ethernet, Wi-Fi, eth, wlan etc. recebe pontos.

Retorno:
- Nome da melhor interface candidata.
- None se nenhuma for encontrada.

Limitacao:
- O usuario ainda deve confirmar a interface no modo interativo.

3.7 obter_ips_reais()
----------------------

Responsabilidade:
- Coletar o baseline antes da VPN.

IPv4:
- Consulta api.ipify.org.

IPv6:
- Consulta o endpoint IPv6 da Cloudflare usando endereco literal.

Proxy:
- As requisicoes usam proxies http/https como None para reduzir interferencia de proxies configurados.

Retorno:

{
  "v4": "endereco_ipv4",
  "v6": "endereco_ipv6_ou_None"
}

Importancia:
- Sem baseline nao e possivel dizer se o IP posterior e o IP original.

3.8 obter_dns_real()
---------------------

Responsabilidade:
- Obter os servidores DNS configurados antes da VPN.

Usa:
- dns.resolver.Resolver().nameservers.

Retorno:
- Lista de servidores DNS.

3.9 listar_interfaces_ativas()
-------------------------------

Responsabilidade:
- Produzir uma lista de interfaces ativas para exibicao.

Retorno:
- Lista ordenada de nomes.

3.10 obter_detalhes_interface(iface)
-------------------------------------

Responsabilidade:
- Mostrar IPs e gateway de uma interface.

Retorno:
- Dicionario com interface, ips e gateway_padrao.

3.11 detectar_ambiente_vpn(nome_processo_exato=None)
-----------------------------------------------------

Responsabilidade:
- Descobrir o ambiente VPN depois que a VPN foi conectada.

Etapas:
1. Captura um snapshot da rede.
2. Procura interface cujo nome pareca VPN.
3. Percorre processos do sistema usando psutil.
4. Aceita nome fornecido explicitamente quando existe.
5. Caso contrario, procura clientes conhecidos.
6. Remove candidatos auxiliares com dnsblock, dns-block ou helper.
7. Prioriza processo com nome igual ao nome da interface.
8. Detecta a interface fisica.

Retorno:

(
  interface_vpn,
  processo_vpn,
  tipo_vpn,
  interface_fisica,
  informacoes_rede
)


4. MODULO core/nucleo_exec.py
==============================

Este modulo e o orquestrador. Ele coordena os testes e define o veredicto.

4.1 Classe VPNSecurityTester
----------------------------

Representa uma auditoria completa.

Atributos principais:
- ips_reais: baseline IPv4/IPv6.
- dns_real: servidores DNS originais.
- vpn_process_name: processo alvo.
- interface_vpn: interface do tunel.
- interface_fisica: placa local.
- info_rede: snapshot inicial.
- resultados: resultados individuais.
- escopo_auditoria: protocolos e limites documentados.

4.2 __init__()
---------------

Recebe os dados coletados por main.py e prepara o escopo.

O escopo informa:
- sistema operacional;
- protocolos monitorados;
- bypass de proxy;
- ausencia de afericao criptografica interna;
- expectativa fail-closed no kill switch.

4.3 run_all_tests()
--------------------

Executa, nesta ordem:

1. Isolamento de Payload UDP.
2. Isolamento HTTP.
3. Privacidade IPv4/IPv6/DNS/DoH/DoT.
4. Isolamento de Rotas Multi-Protocolo.
5. Kill Switch.

Cada teste passa pelo _executar_com_protecao().

Depois:
- gera o resumo;
- salva JSON se solicitado;
- retorna o relatorio.

4.4 _executar_com_protecao(funcao, *args)
------------------------------------------

Recebe:
- funcao do teste;
- argumentos necessarios.

Comportamento:
- executa a funcao;
- captura qualquer excecao;
- devolve status ERRO e detalhes.

Beneficio:
- Uma falha em um teste nao apaga os resultados dos testes seguintes.

4.5 _avaliar_politica_resultado()
---------------------------------

Estados aprovados:
- SUCESSO;
- ISOLADO;
- BLOQUEADO.

Prioridade:
1. FALHA -> REPROVADO.
2. ERRO ou INCONCLUSIVO -> NAO COMPROVADO.
3. Todos aprovados -> APROVADO NO ESCOPO.

Esse metodo evita que um resultado parcial seja apresentado como seguranca completa.

4.6 _gerar_relatorio()
----------------------

Produz duas saidas:

Saida no terminal:
- grupo APROVADOS;
- grupo INCONCLUSIVOS;
- grupo FALHAS;
- grupo ERROS;
- privacidade detalhada por IPv4, IPv6, DNS e DoH/DoT;
- veredicto final.

Saida estruturada:
- timestamp;
- veredicto;
- escopo;
- baseline IP;
- baseline DNS;
- processo VPN;
- interfaces;
- resultados individuais;
- estado inicial da rede.

4.7 _imprimir_grupo(itens)
---------------------------

Recebe uma lista de pares teste/status.

- Imprime cada item.
- Imprime nenhum quando a lista esta vazia.

4.8 _salvar_relatorio(relatorio)
---------------------------------

Cria nome de arquivo baseado no processo VPN e no horario.

Usa:
- open(..., encoding='utf-8');
- json.dump(..., indent=2, ensure_ascii=False).

Retorno:
- True quando salva;
- False quando ocorre erro.


5. TESTE 1 - ISOLAMENTO DE PAYLOAD
===================================

Arquivo: tests/test_1_isolamento_payload.py

Funcao: executar(interface_fisica, interface_vpn)

Objetivo:
- Descobrir se um payload conhecido aparece em texto claro na interface fisica.

Payload:
- b"VPN_TEST_PAYLOAD".

Destino:
- 8.8.8.8:9999.

Filtro BPF:
- UDP;
- host de destino;
- porta de destino.

Etapas:
1. Cria AsyncSniffer para Ethernet.
2. Cria AsyncSniffer para a VPN.
3. Inicia os dois sniffers.
4. Aguarda a captura estar pronta.
5. Envia o payload tres vezes.
6. Para os sniffers.
7. Procura a assinatura na camada Raw.

Resultados:
- FALHA: assinatura apareceu na fisica.
- ISOLADO: assinatura apareceu somente na VPN.
- INCONCLUSIVO: socket enviou, mas nenhum sensor observou.
- ERRO: motor Scapy gerou excecao.

O que este teste nao prova:
- algoritmo criptografico;
- autenticacao;
- integridade criptografica;
- resistencia a replay;
- entrega no destino remoto.


6. TESTE 2 - ISOLAMENTO HTTP
=============================

Arquivo: tests/test_2_isolamento_http.py

Funcao: executar(interface_fisica, interface_vpn)

Objetivo:
- Verificar se uma requisicao TCP/80 aparece fora do tunel.

Etapas:
1. Resolve neverssl.com.
2. Usa o IP resolvido no filtro BPF.
3. Cria sniffers fisico e VPN.
4. Faz requisicao HTTP direta para o IP.
5. Envia Host: neverssl.com.
6. Captura pacotes TCP/IP relacionados ao destino.

Resultados:
- FALHA: pacotes do alvo na interface fisica.
- ISOLADO: pacotes do alvo somente na VPN.
- INCONCLUSIVO: requisicao falhou ou nao houve evidencia.
- ERRO: falha na captura ou processamento.

Limitacao:
- O teste valida isolamento de trafego, nao integridade do conteudo HTTP.


7. TESTE 3 - PRIVACIDADE
=========================

Arquivo: tests/test_3_privacidade.py

Funcao: executar(ips_reais, dns_real, interface_fisica, interface_vpn)

Objetivo:
- Avaliar exposicao de IPv4, IPv6, DNS tradicional, DoH e DoT.

7.1 Resultado inicial
---------------------
O dicionario resultado guarda:
- status;
- detalhes;
- ip_detectado;
- dominio_dns;
- contagens de pacotes DNS;
- protocolos DNS;
- ipv4_status;
- ipv6_status;
- dns_status;
- doh_dot_status.

7.2 IPv4
--------
- Consulta api.ipify.org.
- Usa Cloudflare como alternativa.
- Compara o IP atual com ips_reais['v4'].

Estados:
- IPv4_VAZADO;
- IPv4_MASCARADO;
- IPv4_INCONCLUSIVO;
- IPv4_ERRO.

7.3 IPv6
--------
- Consulta endpoint IPv6 da Cloudflare.
- Compara o resultado com ips_reais['v6'].

Estados:
- IPv6_VAZADO;
- IPv6_ATIVO_MASCARADO;
- IPv6_INCONCLUSIVO;
- IPv6_ERRO.

Timeout nao e considerado automaticamente como bloqueio confirmado.

7.4 DNS tradicional
-------------------
- Cria subdominio com timestamp para reduzir cache.
- Monitora port 53 em ambas as interfaces.
- Executa socket.getaddrinfo().
- Conta pacotes fisicos e VPN.
- Identifica TCP ou UDP quando possivel.

7.5 DoH
-------
- Tenta acesso HTTPS a 1.1.1.1/dns-query.
- Usa Host cloudflare-dns.com.
- O teste verifica a interface do caminho.
- Nao tenta ler o conteudo criptografado.

7.6 DoT
-------
- Abre conexao TCP para 1.1.1.1:853.
- Usa TLS com server_hostname cloudflare-dns.com.
- Verifica se o caminho aparece na interface correta.

7.7 Prioridade
--------------
A funcao combina os resultados:
- qualquer vazamento -> FALHA;
- erro -> ERRO;
- inconclusivo -> INCONCLUSIVO;
- somente evidencias isoladas -> ISOLADO.


8. TESTE 4 - ISOLAMENTO DE ROTAS
=================================

Arquivo: tests/test_4_isolamento_rota.py

Funcao: executar(interface_fisica, interface_vpn)

Destinos TCP IPv4:
- 1.1.1.1:80;
- 1.1.1.1:443;
- 8.8.8.8:443.

Destino TCP IPv6:
- 2606:4700:4700::1111:443.

Destinos UDP:
- 8.8.8.8:53;
- 1.1.1.1:443.

Etapas:
1. Inicia sniffers fisico e VPN.
2. Abre sockets TCP diretos.
3. Envia datagramas UDP.
4. Aguarda pacotes.
5. Para sniffers.
6. Procura SYN TCP e pacotes UDP.

Resultados:
- FALHA: pacote observado na interface fisica.
- ISOLADO: pacotes observados somente na VPN.
- INCONCLUSIVO: tentativa nao observada.
- ERRO: falha do mecanismo.

Limitacao:
- O teste ocorre com a VPN ativa.
- Nao substitui o teste de queda/kill switch.


9. TESTE 5 - KILL SWITCH
=========================

Arquivo: tests/test_5_killswitch.py

Funcao: executar(nome_processo_vpn, interface_fisica, interface_vpn)

Objetivo:
- Simular queda do processo principal e verificar se trafego TCP escapa pela interface fisica.

Etapas:
1. Captura rotas antes.
2. Verifica interface VPN antes.
3. Localiza processo pelo nome exato.
4. Recusa nomes auxiliares.
5. Inicia sniffer fisico antes da queda.
6. Encerra o processo.
7. Aguarda wait(timeout=5).
8. Confirma is_running() como falso.
9. Registra hora_da_morte.
10. Captura rotas e interface depois.
11. Faz cinco conexoes TCP diretas para 8.8.4.4:443.
12. Para captura.
13. Mantem apenas SYNs posteriores a hora_da_morte.

Campos de evidencia:
- tentativas_pos_queda;
- syns_pos_queda;
- captura_confirmada;
- processo_terminou;
- rotas_antes;
- rotas_depois;
- interface_vpn_antes;
- interface_vpn_depois.

Resultados:
- BLOQUEADO: tentativas ocorreram e nenhum SYN escapou.
- FALHA: SYN posterior apareceu na interface fisica.
- INCONCLUSIVO: processo ou captura nao puderam ser confirmados.
- ERRO: permissao negada ou falha grave.

ATENCAO:
- Este teste encerra a VPN.
- E necessario reconectar a VPN depois.
- Deve ser executado com privilegio administrativo.

make_tester()

test_policy_accepts_only_approved_states()

 test_payload_signature_matches_orchestrator()

$env:VPN_INTEGRATION = "1"
python -m unittest tests.test_integracao_rede -v


12. LIMITES DO CODIGO
=====================

- O projeto nao examina diretamente o algoritmo criptografico da VPN.
- DoH e DoT sao avaliados pela rota, nao pelo conteudo.
- IPv6 exige conectividade nativa no baseline para comparacao completa.
- Uma captura vazia pode ser inconclusiva, e nao prova automatica de seguranca.
- A descoberta de processo e baseada em nomes e heuristicas.
- O kill switch testa um conjunto de destinos e protocolos, nao todos os possiveis.
- Os testes reais dependem de Npcap, permissao administrativa e interfaces corretas.

Conclusao de estudo
-------------------
O codigo implementa uma ferramenta experimental de auditoria de isolamento e privacidade de VPN. Sua principal contribuicao e automatizar a coleta de evidencias e evitar que resultados inconclusivos sejam apresentados como aprovacao de seguranca.
